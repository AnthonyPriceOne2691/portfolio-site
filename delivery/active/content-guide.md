# Требования к контенту проекта

Что нужно подготовить, чтобы добавить проект на витрину. Цифры не на глаз —
замерены на собранном сайте (Chromium, кириллица как худший случай).

## 1. Добавить проект = один файл

```
src/content/projects/<slug>.md
```

Кода не трогаем: проект появится в списке сам.

⚠ Сайт **одноязычный, английский** с 2026-09-22. Файлов было два, русский и
английский, и файл без пары валил сборку — русская версия снята целиком,
вместе с ней ушли зеркальная коллекция и проверка пар. Текст карточки
пишется **по-английски**: его читает тот, для кого сайт и сделан.

## 2. Frontmatter

| Поле | Обяз. | Что это |
|---|---|---|
| `title` | да | Название проекта |
| `oneLiner` | да | Одна фраза: что это и кому |
| `metric` | да | **Одна** цифра результата, не список |
| `status` | да | `production` / `local-demo` / `poc` |
| `stack` | да | Массив. **На карточке видны первые 5** — ставьте главное вперёд |
| `contract` | да | Чем поведение ограничено (блок «Под контрактом») |
| `proof` | да | Минимум одно из: `github`, `case`, `video`, `teaser`, `poster` |
| `order` | да | Порядок на главной, целое ≥ 0 |
| `updated` | да | Дата |
| `draft` | — | `true` — не публикуется |

Тело файла (после frontmatter) — раскрывающаяся часть карточки на главной.
Отдельных страниц у проектов нет.

## 3. Как писать карточку

Карточку читают **между делом**, в ленте из четырёх таких же. Решение —
раскрыть или пролистать — принимается по метрике и одной фразе. Всё остальное
читают уже те, кто раскрыл.

Правило одно: **короче и конкретнее**. Длинный текст не ломает вёрстку, он
теряет читателя.

### Метрика

Цифра, которую можно **пересказать не глядя**. Не «качественный код», а число.

| Не так | Так |
|---|---|
| Высокая надёжность | `97.9% доставки` |
| Много тестов | `~180 тестов` |
| Быстрые ответы | `~3 с на реплику` |

Если цифры нет — её обычно можно посчитать: строки, запросы, время, объём.
Оценка честнее пустого прилагательного: `~30 сервисов` работает, «масштабная
архитектура» — нет.

### Одна фраза

**Что делает и для кого.** Не из чего сделано — стек показан отдельной строкой.

> Один оператор ведёт то, на что уходила команда из пяти: поиск площадок,
> переговоры письмами с участием AI, оплаты и мониторинг размещений.

Работает, потому что начинается с результата для человека, а не с технологии.
Сравните: «SaaS-платформа на FastAPI и React для автоматизации аутрич-процессов»
— то же самое, но читателю не сказано ничего.

Выкинуть: «современный», «инновационный», «мощный», «гибкий»,
«оптимизированный». Они не несут смысла и занимают место, которого мало.

### Тело карточки

3–5 пунктов, каждый — факт с числом или ограничением. Не пересказ фразы выше,
а то, что в неё не влезло. Сейчас у всех проектов 5–9 строк, 290–450 символов —
это верхняя граница, не цель.

## 3.1. Пределы длины

Считано на 360px (узкий экран, кириллица — худший случай).

| Поле | Цель | Предел |
|---|---|---|
| `metric` | **8–18** | 34 (дальше третья строка) |
| `title` | **до 32** | 51 |
| `oneLiner` | **90–135** (см. ниже) | 84 = три строки на 360px |
| `stack` | первые **5** пунктов, до 45 | 38 в одну строку на 360px |

Цель для фразы — **две строки на ноутбуке**. Предел двух строк: 156 символов
при окне 1280px, но уже **138 при 1024px** — на нём и надо ориентироваться,
иначе на обычном ноутбуке фраза поедет в три строки. Отсюда 135.

Длинный текст карточку **не ломает** — она просто растёт. Ломает другое:

> **Неразрывный токен** (URL, длинное составное слово) даёт горизонтальный
> скролл. Максимум на 360px: `metric` — 14 символов, `title` — 15, `oneLiner` —
> 19, `stack` — 22. Это стережёт тест B7.

## 4. Видео: три разных файла

Их путают чаще всего. Это **не** один ролик в трёх размерах.

| Ключ | Что | Где играет |
|---|---|---|
| `teaser` | Короткий немой луп | В карточке, **при наведении** |
| `poster` | Один кадр | Под тизером, пока он не загрузился |
| `video` | Полное демо | Ссылкой «Смотреть демо» в раскрытой карточке |

### teaser — локальный файл

- **8–15 секунд**, зацикленный, **без звуковой дорожки** (не «тихий» — без неё)
- **1280×720**, строго **16:9**: фрейм обрезает по `object-fit: cover`
- Формат **MP4 / H.264 / yuv420p** + `faststart` — единственный, который играет
  везде, включая Safari
- **до 1.5 МБ.** Грузится только при наведении (`preload="none"`), но грузится
  целиком и сразу
- Читается **без звука и без подписи**: видно действие, а не заставку

Больше 720p смысла нет: фрейм рендерится максимум **386 CSS-пикселей**
(772 при 2× DPR). 1080p — это лишние байты, которых не видно.

```
ffmpeg -i src.mov -t 12 -an -vf "scale=1280:720:force_original_aspect_ratio=increase,crop=1280:720" \
  -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 26 -movflags +faststart teaser.mp4
```

### poster — локальный файл

1280×720, JPEG или WebP, **до 150 КБ**. Первый осмысленный кадр тизера.

### video — полное демо

- **1–2 минуты**, со звуком
- Можно **файлом рядом с сайтом** (`/demo-<slug>.mp4`) или внешней ссылкой
  (YouTube, Vimeo). Схема принимает оба вида
- Свой файл (`/demo-<slug>.mp4`) **встраивается плеером** прямо в раскрытую
  карточку. Внешняя ссылка остаётся ссылкой: YouTube в `<video>` не играет, для
  него нужен чужой `<iframe>` со скриптами и куками
- Плеер с `preload="none"` — файл не качается, пока не нажали play. Раскрытие
  карточки ничего не грузит

**Бюджет — 25 МиБ на файл.** Столько разрешает Cloudflare Pages (плейсхолдер
домена в `astro.config.mjs` указывает на него); у других бесплатных хостингов
лимит выше, но 25 МиБ — самая тесная рамка, и уложившись в неё вы свободны в
выборе. Это диктует битрейт, а не «экспорт как получится»:

| Длина | Общий битрейт | Вес |
|---|---|---|
| 1 мин | до 2.6 Мбит/с | ~19 МБ |
| 1.5 мин | до 1.8 Мбит/с | ~20 МБ |
| **2 мин** | **до 1.4 Мбит/с** | **~21 МБ** |

Двух минут при 720p достаточно: скринкаст сжимается хорошо, движения мало.

```
ffmpeg -i src.mov -vf scale=1280:-2 -c:v libx264 -preset slow -crf 24   -maxrate 1.3M -bufsize 2.6M -c:a aac -b:a 96k -movflags +faststart demo-<slug>.mp4
```

`-maxrate` здесь важнее `-crf`: он не даёт сложной сцене выбить файл за лимит.
`+faststart` переносит оглавление в начало — без него браузер ждёт загрузки
всего файла, прежде чем показать первый кадр.

### Куда всё кладётся

Всё в `public/` — оттуда Astro копирует в корень сайта как есть:

```
public/teaser-<slug>.mp4    →  proof.teaser: "/teaser-<slug>.mp4"
public/poster-<slug>.jpg    →  proof.poster: "/poster-<slug>.jpg"
public/demo-<slug>.mp4      →  proof.video:  "/demo-<slug>.mp4"
public/cv.pdf               →  кнопка «Скачать резюме» на /about/
```

⚠ Путь обязан начинаться с `/`. Относительный вид `teaser.mp4` резолвится от
адреса страницы и молча ломается — схема такой отклоняет.

⚠ Видео лежат в git и **не сжимаются дельтой**: каждая перезаливка ролика
добавляет в историю ещё столько же. Четыре демо по 20 МБ — это 80 МБ репозитория
и +20 МБ за каждую переснятую версию. Если начнёт мешать — выносить в R2 или
на YouTube, менять придётся одну строку в md.

## 5. Проверка перед коммитом

```
npm run build
```

Прогоняет типы, сборку и 56 тестов: схему, контраст, отсутствие
горизонтального скролла на 360/390/414, аккордеон, контакты.

## 6. Хостинг

Не выбран. Бесплатные варианты: **Cloudflare Pages** (безлимитный трафик,
25 МиБ на файл), GitHub Pages (100 МБ на файл, но правила не приветствуют
раздачу медиа), Netlify и Vercel Hobby (по 100 ГБ трафика в месяц). Лимиты
бесплатных тарифов меняются — сверяться перед выбором.

### Что нужно для Cloudflare Pages

1. Регистрация: <https://dash.cloudflare.com/sign-up> — бесплатный тариф, карта
   не нужна.
2. Подключить репозиторий: на главной панели **Create app** («Ship something
   new») → импорт из Git → GitHub → выдать доступ к репозиторию. В сайдбаре то
   же лежит в **Compute → Workers & Pages → Create**.

   <!-- ⚠ Путь назван двумя способами нарочно: Cloudflare перенёс Pages внутрь
        Workers и переименовал разделы. Если и эти названия разойдутся с
        панелью — ищите «Pages» или «connect to Git», суть шага не меняется. -->

3. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Build command | **`npm run build:site`** |
   | Deploy command | `npx wrangler deploy` (подставляется само) |
   | Переменная `NODE_VERSION` | `22` |

   ⚠ Если панель предлагает preset «Astro», он подставит `npm run build` сам —
   **перепишите вручную** на `build:site`. Обычный `build` цепочкой зовёт
   `npm test`, а Playwright на сборщике отсутствует.

   ⚠ Панель ведёт в флоу **Workers**, а не Pages: деплоем занимается
   `npx wrangler deploy`, и он читает `wrangler.toml` ИЗ РЕПОЗИТОРИЯ. Файл
   лежит в корне; без него сборка проходит, а деплой падает на «no config
   found» — ошибка приезжает после зелёной сборки. Каталог сборки задан там
   (`[assets] directory = "./dist"`), поэтому отдельного поля «output
   directory» в этом флоу нет.

4. Поменять `site` в `astro.config.mjs` на выданный домен.

**Развёрнуто 2026-09-21:** <https://portfolio-site.anthony-priceone.workers.dev>
Каждый push в `main` деплоится сам. Появится свой домен — менять `site` в
`astro.config.mjs` одной строкой.

**⚠ Команда сборки — `build:site`, а не `build`.** Обычный `npm run build`
цепочкой зовёт `npm test`, а там Playwright: на сборщике Cloudflare браузера
нет, и деплой упадёт. Ставить браузер туда незачем — полный гейт и так гоняется
в GitHub Actions на каждый push (`.github/workflows/quality.yml`). Разделение
правильное: CI судит код, хостинг просто собирает.

**⚠ `site` — не косметика.** Сейчас там заглушка `https://example.pages.dev`.
От неё зависят canonical, hreflang, sitemap и `og:image` — то есть превью
ссылки в Telegram, hh и LinkedIn. С чужим доменом превью будет ссылаться в
никуда.

## Фото в герое главной

Положить в `public/` под именем **`photo`** с любым из расширений (проверяются
в этом порядке): `.jpg`, `.jpeg`, `.png`, `.webp`.

```
public/photo.jpg
```

- **квадратное или близко к нему** — круг обрезает по `object-fit: cover`,
  но сильно вытянутый портрет потеряет голову или подбородок
- **не меньше 400×400** — круг рендерится в 200 CSS-пикселей, на экране с
  удвоенной плотностью нужно вдвое больше
- **до 200 КБ**, JPEG или WebP

Правок в коде не нужно: пока файла нет, в круге стоит стеклянная заглушка,
которая держит раскладку; появится файл — подставится сам, при следующей
сборке. Битой картинки не будет ни в один момент — это под тестом.

### Видео о себе в том же кружке

Круг умеет быть плеером. Положите рядом с фотографией:

```
public/intro.mp4
```

- **25–40 секунд**, со звуком, лицо крупно и почти на весь кадр
- **квадрат, не меньше 400×400** — те же 200 CSS-пикселей при 2× DPR.
  Прямоугольный кадр круг обрежет по бокам, и половина лица уйдёт
- H.264 / yuv420p / `+faststart`, как и остальные видео

```
ffmpeg -i src.mov -vf "scale=600:600:force_original_aspect_ratio=increase,crop=600:600" \
  -c:v libx264 -preset slow -crf 24 -c:a aac -b:a 96k -movflags +faststart intro.mp4
```

**Фото обязательно.** Без `photo.*` видео не подставляется вовсе: постером
служит именно фотография, а круг, чёрный до первого клика, — это та же пустая
дыра, ради запрета которой стоит заглушка.

Играет **по клику**, а не по наведению, как тизеры в карточках: говорящая
голова без звука выглядит сломанной, а звук по наведению браузер не разрешит.
Повторный клик — пауза, конец ролика возвращает фотографию. До клика не
качается ни байта (`preload="none"`).

Ролик — **на английском**: сайт одноязычный, и кружок ровно тем и ценен, что
показывает живую английскую речь.

## Картинки сайта

Превью ссылки и фавикон **генерируются**, а не рисуются:

```
node scripts/make-assets.mjs
```

Берут холст и цвета из `src/styles/*.css`, имя и роль из словаря, метрики из
коллекции проектов. Поменяли палитру, роль или метрику — перезапустите и
закоммитьте `public/og.jpg`, `public/og-en.jpg`, `public/favicon-32.png`,
`public/apple-touch-icon.png`. Нарисованная руками картинка разошлась бы с
сайтом в первый же день, и заметить это было бы некому: превью видит рекрутёр,
а не владелец.
