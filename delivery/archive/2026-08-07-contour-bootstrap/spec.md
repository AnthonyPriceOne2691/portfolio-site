# Spec: контур на greenfield — portfolio-site под канон-стеком

## Problem

Сайт-визитка начинается с нуля. Момент единственный: контур ставится на пустое
дерево, поэтому все снимки стартуют с жёсткого нуля, и ни один гейт не приходится
вводить «постепенно» — на легаси это стоило бы отдельной поставки.

Вторая задача, не менее важная: **канон-стек ни разу не разворачивался на
не-Python проекте.** Карта ролей §Применимость (какой гейт чем заменяется на
чужом стеке) написана и не проверена. Эта поставка её проверяет.

## Users / stakeholders

Anthony — единственный владелец и пользователь репозитория. Читатели сайта
появятся следующей поставкой (MVP), на эту не влияют.

## In scope

- Delivery-каркас (§7.2): дерево `delivery/`, `delivery_check.py`,
  `delivery_metrics.py`, `.claude/settings.json`, constitution под этот продукт.
- Каркас Astro в объёме, достаточном, чтобы гейтам было что смотреть: `package.json`,
  конфиг, `src/pages/index.astro`, схема контента (zod) по design §8.2.1.
- CQG, адаптированный под TS-стек: гейты, применимые к статике, + **явная карта
  ролей** — что исключено и почему (`STACK-ACCEPTANCE.md`).
- CI (§8.3) и гейт мержа (§8.5.1–8.5.2): `merge_guard.sh`, `check_ci_status.sh`,
  pre-push, `main-guard`.
- Приёмка по AGENT_STACK §6 с честными отметками.

## Out of scope

- Контент сайта, вёрстка, дизайн, видео — следующая поставка (design §11, Phase 1).
- OKF: канона домена у витрины нет, слой объявлен `absent` сознательно.
- Домен, аналитика, деплой на Cloudflare Pages — Phase 1/2 дизайн-документа.

## Acceptance (observable)

- [ ] `pre-commit run --all-files` при **чистом env** зелёный, и каждый гейт формы
      печатает непустое число просмотренных файлов (§6, «зелёный гейт, который
      ничего не видит, хуже красного»).
- [ ] `bash scripts/lint/check_gate_coverage.sh` — 0 незаполненных шаблонов, каждый
      неподключённый гейт имеет причину в `not_wired_reason()`.
- [ ] `python3 scripts/lint/contour_doctor.py` — `DEAD 0`.
- [ ] `python3 scripts/delivery_check.py` — 0 error(s).
- [ ] `npm run build` собирает сайт; сломанный frontmatter **валит сборку**
      (design §8.2.1), а не молча ломает вёрстку.
- [ ] CI зелёный на ветке, `merge_guard.sh` пропускает мерж только на зелёном.
- [ ] `STACK-ACCEPTANCE.md` заполнен: каждая непокрытая область названа словами.

## Non-functional

- Гейты на коммите укладываются в бюджет §8.6 (≤10 с суммарно): статика,
  тяжёлых линтеров нет.
- Хостинг остаётся бесплатным; сборка не требует сети сверх `npm ci`.

## Open questions

- `jscpd` и `eslint` ставятся как devDependencies — это две прямые зависимости
  контура, а не продукта. Объявляются строками `new_dependency:` или считаются
  механикой контура? (Решение — в `decisions.md` этой поставки.)
- Нужен ли `diff-coverage` на статическом сайте, где тестов пока нет: подключать
  сразу с порогом 0 или объявить `not_wired_reason()` до появления тестов.
